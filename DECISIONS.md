# Decisions

Calls made without asking, with the reason. Design-level conflicts between proposals are in the table at the top of DESIGN.md.

- **Name**: Cantator, after cantor, the person who leads singing. The repo stays `live-audio-player`. The Xcode project, target, scheme and `CantorCore` package keep the old name, and so do the bundle ID, `~/Library/Application Support/Cantor`, `~/Music/Cantor` and the keychain item, so renaming the app loses no library, token or folder permission.
- **Developer ID signed and notarized for release**: Release builds use the Developer ID Application certificate for team 6RHHE8NEYA with the hardened runtime and no entitlements; nothing the app does needs one. Debug stays ad hoc.
- **Unsandboxed**: single-operator tool. Sandbox bookmarks can go stale when Drive remounts, and changing the system alert device needs no entitlement outside the sandbox. Not App Store distributable.
- **macOS 15 minimum**: gives `Synchronization.Atomic` for render-thread state with no C shim.
- **Logic in a local Swift package**: `swift test` runs without launching the app, so tests can never touch real audio output.
- **Swift language mode 5**: render-thread code uses unsafe pointers on purpose. Strict mode would add noise without improving it.
- **No third-party dependencies**: nothing to break or update before a Sunday.
- **FFmpeg only if it's installed**: Import uses it for file types macOS can't read, but never bundles it, so Cantator still builds and runs without it. Without it, Import says FFmpeg is needed for that file type and leaves the rest to the operator.
- **Originals are never moved, renamed or deleted**: Make Local copies to `~/Music/Cantor`, so Drive sharing keeps working.
- **Points are per track, not per cue** in v1.
- **Only one house cue at a time**: arming while something plays is refused. Choir playback has no crossfades.
- **No marker jumps while live**: Hold first, then jump, then GO. A jump while the house hears it would be a surprise.
- **Hold resumes through GO**, so a stray key cannot restart a held track.
- **Panic fade is 1.5 s, adjustable in Settings. End-of-song uses the track's saved fade.**
- **A manual fade that would run past the end marker is shortened to land on it.**
- **Fade curve**: equal-power cosine. It sounds even and reaches exact silence.
- **Suggested end = last point above -50 dBFS, and it is not automatically saved**: the operator has to accept it, because "has an end point" should mean a person checked it.
- **AI uses the operator's Claude account, not an API key**: Cantator runs their installed, unmodified Claude Code (`claude -p`) with its existing login. API variables are removed from its environment, and a Claude Code set up with an API key is refused. Optional: name matching works without it.
- **This is for the owner's own use**: Anthropic's terms say products built for other people should use API keys and may not route requests through subscription credentials on users' behalf. If Cantator is ever given to anyone else, this part has to change.
- **Claude Code call**: no tools, no settings, no MCP servers, no saved session, low effort, from an empty folder, with the prompt on stdin. `--bare` is not used because it skips the account login.
- **Model**: blank uses the account's default, changeable in Settings.
- **Cantator watches the folders, Claude only reads names**: Claude gets no file system access. Cantator sends it filenames, two folder names, durations and tags, which is all a classifier could use anyway since it cannot hear the audio.
- **Planning Center with the token when one is saved, the Claude connector otherwise**: the connector was the operator's ask, and it replaces a pasted Personal Access Token with their own Planning Center sign-in and permissions. It is the one place Claude reads more than names: through the connector it sees item titles and descriptions, which can hold people's names. To keep the data exact, Claude gets no built-in tools and only the three read-only Services tools (the two People write tools are denied too), and Cantator builds the plans from the tool results in Claude Code's stream-json output instead of from Claude's reply. A plan whose item count disagrees keeps its saved copy. Later the operator asked that a saved token come first, since it is faster, gives attachment filenames and uses no Claude usage, so the source picker went: a saved token is read first, and the connector is used when there is none or the token fails and Claude is on.
- **Categories are library tags**: the pop-up's category is the same tag that makes a library sidebar section, so there is one way to group tracks. Defaults are choir, special, offertory, prelude, postlude, children and walk-in, plus any tag already in use.
- **"New" means arrived after Cantator started watching that folder**, by the file's added-to-folder date. Otherwise adding a folder, or the first run, would put every existing file in front of the operator.
- **A loaded service holds all pop-ups**, even between songs. Loading is the signal that the service has started. Claude may still be asked while a service is loaded and idle, so pop-ups are ready the moment it is unloaded.
- **Stems are found by Cantator, not Claude**: names, folders and same-length sets are on disk and free to check, and a stem set is clearest when seen as a set, which a batch of filenames sent to Claude may split. Exclusion only hides a file from matching and lists, so a wrong guess costs a click in Excluded, while a missed stem only adds a candidate the operator still has to confirm.
- **EQ is static and per track**: a high-pass, six bell or shelf bands and a low-pass at 12 dB per octave, plus output gain. No dynamics, sidechain or mid/side: the job is fixing a mix that is too boomy or dull, not mastering. RBJ biquads in double precision run inside the playback kernel, so nothing is rendered ahead and an EQ costs nothing while flat.
- **EQ edits reach preview at once and house at the next arm**: preview gets new coefficients through the kernel's command ring while it plays, so the operator hears each knob move. A cue already armed or playing keeps the EQ it started with, like every other track edit.
- **Loudness matching measures the file as mixed**: the EQ does not change the matched gain. A big boost can raise the level and the peaks, so the OUT knob is there to bring it back.
- **Accepting a suggested service item confirms the match**: the operator is looking at it and pressing Accept, which is the confirmation the rule requires.
- **Claude status lives in Settings > Claude**: it used to be always visible in the sidebar, which the operator found took room the library needed. A failed request still says so in an alert, with Sign In to Claude when that is the cause. Amber only when something needs fixing, never green, because green means LIVE. The check is `claude auth status`, which uses no account usage, and it is skipped while a cue is armed or playing.
- **Every playback is copied to ~/Music/Cantor by default**: it began as Downloads and Desktop only, since those get cleaned out; the operator wanted every file filed as a playback kept in Cantator, wherever it came from. The checkbox in New Files turns it off and is remembered. Copies run one at a time, since sorting hundreds of files must not start hundreds of Drive downloads, and wait while a cue is engaged.
- **Remembered files follow the song, not a look-alike title**: an item with a Planning Center song is only matched to files confirmed for that song. Without a song, a file is remembered by title, numbers included ("Psalm 23" is not "Psalm 91"), and a title with nothing left once words such as choir, special and solo are dropped is not remembered at all. A file remembered only by title is offered, never confirmed automatically, since items like "Special Music" carry a different song each week.
- **The plan's notes say what runs on tracks**: an item is a playback when its title, arrangement or notes have a track word (track, playback, negativ, pista), so "Choir - tracks" is one and "Choir - band SOLO orange mic" is not. Marking every song made live worship look like missing playbacks. A choice is remembered per song, and a sync updates unconfirmed items when their notes change. A track word wins over a remembered Not Needed, since the notes are written for that service and the memory is for the song in general; a remembered Needed still turns on an item whose notes say nothing.
- **Scores cap at 0.97 for string and LLM matches**: 100% would read as certainty.
- **Strong matches confirm themselves**: the operator asked for it, since a fresh file for a marked item should just land. Only Proposed matches (0.85 or more, 0.08 clear of the next), outside Show Mode. They show as Auto-confirmed, and Clear Match on an item stops Cantor confirming there again. Operator confirmations still teach the matcher; automatic ones don't.
- **Hardware tests are opt-in and use virtual devices only**: `swift test` alone never opens an audio device.
- **`SelfCheck` is compiled in Debug only**: it drives the real flow with a throwaway home and virtual devices.
- **Sleep with a cue armed or playing counts as device loss**: wake always lands in a fault the operator acknowledges, never in sound.
- **Transport keys are not menu shortcuts**: a bare-key shortcut would fire from a text field in Settings. The keys are shown in the menu titles instead.
- **Show Mode is optional**: the operator found requiring it before Arm and GO one step too far. The transport works in the Show view, and leaving that view through the sidebar disarms, so an armed cue never waits unseen. Show Mode stays as a lock on editing.
- **The sidebar shows the program in Show Mode**: the operator wanted to follow the service, not just its playback cues. Its links led to text fields, which is why Show Mode used to close it; read-only program rows have no such risk.
- **The sidebar is a system sidebar list**: drawn rows in a stack laid themselves out wider than the column and slid off the window's left edge when the sidebar was dragged wider. Apple's Liquid Glass guidance is to build the sidebar from standard parts and leave its background, selection and row sizes to the system, so both sidebars are `List`s in the sidebar style, with sections, labels, badges and a disclosure group. Show and Pre-Service Check stay in view in a bar pinned above the services, and the library and the outputs in one pinned under them; only the services scroll, although Apple advises against critical status at a sidebar's bottom edge, because the operator reads them there. The pinned parts are further sidebar lists sharing the selection, each as tall as its rows; the library never takes more than half the sidebar. The view beside the sidebar always keeps the Show view's minimum width, so the split view stops the divider, or holds the window wider, rather than letting the columns overflow the window.
- **Standalone is the default for a fresh install**: the first launch asks whether services are built here or synced from Planning Center, and nothing else is needed to run a service. Settings saved before the question existed read as Planning Center, so no one who already uses it is asked.
- **Claude is its own switch, not part of the Planning Center choice**: it files new files and ranks matches for hand-built services too. Off by default when building here; the Planning Center answer turns it on, as it always was. Off, no trace of it shows, and New Files just says the title was guessed from the name.
- **Copies and templates never carry tracks**: the structure of a service repeats week to week, the songs don't, and a copied track is a way for last week's song to play. Tracks are the one thing the operator always chooses.
- **An item typed by hand is never confirmed by Cantator**: the operator is choosing its track, so Looks Like proposes and only Use assigns. Synced items keep confirming themselves, as the operator asked.
- **Services built here survive every sync and leave on a clock**: a sync knows nothing about them, so it keeps them all; past ones fold away and leave after eight weeks (adjustable, or never) unless loaded. The tracks keep their play history.
- **No test tone**: a tone on the house output outside Arm and GO would break the one rule that makes "never the house by accident" checkable. Arm + Play with any track does the trim check.
- **Updates through Sparkle and GitHub Releases**: the repository is already public and `gh` is set up, and the feed address on the latest release never changes. Updates are offered, never installed silently, and never checked or installed while the show is busy or the Show view is up, since an update window would take the transport keys.
- **House and cue may share a device, never a pair**: the church runs everything through Dante Virtual Soundcard, so two devices were not available. Each output engine's channel map sends silence to every channel but its own pair, so cue audio still cannot reach the house pair, and a device with two outputs or fewer only has 1-2, so it still can't be both.
- **A repeated A says nothing**: pressing A again to be sure put "Finish the current cue first" in front of the operator mid-service. A while a cue is armed or playing now does nothing at all. In Simple, a different picked song still replaces the armed one.
- **`[` and `]` work from arm, not just once playing**: the operator expected them to work on the armed cue and saw nothing change. The END readout shows the run's end.
- **Clicking a cue points at it**: the choir may change the order without Planning Center being updated. A click in the cue list or the Show Mode program does what the arrow keys do, only while nothing is engaged, and never plays.
- **Double-clicking a service goes straight to the show**: load, open Show, Show Mode on was four clicks. The double-click does all three; it only loads and locks, and A and GO still start sound.
- **`[` and `]` save the end with the track**: the operator wanted an end fixed during a service to stay fixed the next time the song is used, and to fix it before arming. Every press is saved at once, like an EQ edit in Show Mode, and with nothing armed it moves the pointed cue's end. This replaces run-only nudges, so a stray press now changes the track until it is moved back; Simple still ignores both keys. For two seconds after a cue ends they do nothing, because the pointer has already moved on and a press meant for the fade would move the next song.
- **Practice services are pinned, not undated**: the operator wanted a service for rehearsals that the date filter and the past-services clean-up leave alone. A pin keeps a service at the top of the list whatever its date, and it works for synced services too, which have dates Planning Center sets. For Pre-Service Check, a pinned Planning Center service still counts by its date, since pinning Sunday's service keeps it Sunday's; a pinned service built here is a practice list and never stands in for a service.
- **Views read the app model through `@AppEnvironment`**: leaving a hand-built service quickly crashed the app, because the service table updated its rows' state labels once more after they had lost the environment, and a plain `@Environment(AppModel.self)` read stops the app when the model is missing. There is only one model, so the wrapper falls back to it and logs the view (category `environment`). A crash in the middle of a service is never worth it for a view that is already going away.
- **New files are reviewed as one list**: the operator had over 550 files, and a pop-up per file made sorting them a day's work. Claude's answers fill a table where several rows change at once, and Apply files them together. Sort with Claude puts library tracks through the same list, since files already in a folder when it was added are never new; a track a service uses stays out, so the list can never take a playback off a service.
- **Practice parts and demos are excluded like stems**: PTX, practice, rehearsal and demo in a name, or practice and rehearsal in a folder, mark audio a choir learns from, never plays. They go to Excluded without Claude, where This Is a Playback brings one back, as for a stem.
- **Tags are a list the operator owns**: they were the seven built-in names plus whatever tracks had, so none could be renamed or removed. The list is saved in settings, starts as the seven, and a rename or delete reaches every track, excluded ones too.
- **A missing end point only matters before trailing silence**: the operator saw tracks flagged that end with the music, where playing to the end of the file is right. A track needs an end point when the analysis finds two seconds or more below -50 dB at the end, has found no sound, or has not run yet.
- **Copies of a playback keep one, by name and length**: the operator's folders held the same songs in several places. A different file name could be a different version, such as a full mix beside its instrumental, with the same length, so only a matching name, ignoring what copying adds, excludes on its own. Look-alike titles stay in Duplicates for the operator's Keep This One. The copy that stays is the one with the most of the operator's work on it, so nothing they set is set aside.
- **Releases run on GitHub Actions**: the notarization profile kept going missing from the release Mac's keychain, and every release asked for the login password to sign. Live RO2EN's releases never needed the operator, because they run on GitHub with the certificate and passwords as repository secrets in a keychain each run creates and deletes. Cantator does the same through the same `scripts/release.sh`, which still works on a Mac.
- **Planning Center items can be deleted until the next Refresh**: the operator wanted to clear rows they don't need, and Planning Center stays the source of the order. A deleted synced item is simply not kept, so Refresh brings it back clean, with no track or choices, rather than a hidden flag that would keep it gone. A swipe only shows Delete, never deletes, because SwiftUI's swipe actions work in lists, not tables, and a stray trackpad gesture mid-service must not take a row out.
